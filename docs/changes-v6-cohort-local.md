## 当前交付

45 校继续复用共享 V6 组合及 Changes 组件，位置、默认折叠、90 天和红绿增减规则保持。其余 42 校的页面、概览和按需事件详情已在本机逐校接通验证；没有逐校 JSX/CSS、服务或完整发布目录。

每校只选近 90 天最近一次实质修订；三校保留原指定代表事件。为 45 个完整事件准备冻结事件、所有条目、实际证据片段和审核材料。新 42 校共 84 份 EN/ZH 候选，加上三校重新绑定的 6 份，共 90 份，批准数为 0。

**84 份新增候选在私有审核包中，不在网站上冒充已审核摘要。** 开发预览白名单仍是原三校、最多六份；正式 reader 仍只接收审核通过的独立包。Cornell/MIT 四份在本机可见候选，EPFL 因证据冲突回到暂缓模板；其余学校在网页显示真实结构化概览和差异，候选正文在 `review.md` 集中检查。没有产出或选择真实批准摘要包。

## 两项修复

1. 规则升为 `tracker-events-1.2.0`。无 Claim ID 的主类别冻结对象按对象 ID 去重，工具单列“工具记录”，其他单列“未编号记录”；不补造 Claim ID，不按相同文字合并不同修订。维护／来源／页面类不当成主类别对象。TUM r3、Yale r3/r4 均为“涉及 1 条（未编号记录 1）”。
2. EPFL 冻结引文确为 “should not”，支持不了已记录 Claim 中的 “must not”。新候选删除“要求性”与登录入口描述，明确证据冲突并附 generationHold，不能打包为公开摘要。原 canonical Claim 和历史 r6 文字没有修改，后续须走记录审核与新修订，不能篡改历史或用摘要掩盖。

完整 475 个历史学校标识、786 个事件，以及每个条目的 ID、原文字、类别、Claim ID、URL 均与上一冻结包一致；本轮变化是规则版本及计数。10 个记录维护分类保留。所有主类事件的零计数已清除，非工具未编号事件共 3 个。45 个 overview 最大 3,378 字节，继续小于 10,240 字节。

## 摘要前的证据检查

`prepareSummaryReviewPacket` 现在从投影输入中读取**同一学校、同一事件、同一旧／新侧**的冻结证据。条目通过 Claim ID 或冻结对象哈希匹配，不能用类似文字、其他版本或 latest 填证据缺口。审核包附原始 snippet、URL、snapshot hash 和定位器，并冻结证据 hash。

生成前筛查 must / should / may / required 等强度提示；检测器只负责指出可能差异，不提供语义批准。否定句、翻译和限定范围可能产生误报。本批 37 校有“需语义核对”提示，不代表 37 校政策错误；没有提示也不代表语义通过。

两校的四份候选明确暂缓：

- EPFL：已确认考试表述的 should-not / must-not 冲突；所附片段也不支持登录入口句。
- Edinburgh：完整事件中一条 ELM 获取条件的暂缓条目没有匹配冻结引文，保留缺口，不截掉该条后声称整次摘要完整。

其余候选也全部 pending。Cornell/MIT 原复核“建议批准”不自动变成新包的批准记录；仍需授权审核人绑定新候选 hash。作者未代填 reviewer 或 approved。带 generationHold 的候选即使输入一份形式上批准的 review，也被打包函数拒绝。

## 批量而不复制页面

新增 `scripts/prepare-change-summary-cohort.ts`，按真实 overview 清单准备每校一个近期完整事件，输出只能在 tracked data 之外；没有新公开路由。读取投影输入一次再复用，不逐校重复读取约 51 MB 输入。

摘要绑定从原三校的 1–5 条试点扩到最多 128 条，保持完整事件而不截断；每语言叶子上限 128 KiB，打包前和读取时检查。当前最多 63 条绑定，最大候选 39,879 字节，90 份总计 1,410,499 字节，主要是完整指纹绑定，正文仍限三个精简段落。公开 manifest 仍为独立摘要 family，不把审核状态写进事件投影。

统一私有入口：`.local/changes-v6-cohort/review-index.json`，绑定同一投影、每校事件、EN/ZH 文件、原始字节 hash、证据包和 pending 审核模板。`review.md` 可一次浏览全批，`schools/{slug}/packet.json` 提供完整依据。新候选由本 Codex 会话按冻结材料起草，没有调用第三方生成服务或上传证据。

## 页面交互修复

本轮逐校实测发现：在 React 接管前展开原生 details，可能错过 onToggle，详情停在“正在加载”。共享组件在挂载时补读已展开的子项，只对实际展开项发请求。用阻塞 Next JavaScript、提前展开、恢复脚本的真实浏览器试验确认能接续加载；未增加额外缓存、默认预取或服务。
