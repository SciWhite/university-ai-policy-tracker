# Changes / V6 分期开发计划（评审修订版）

2026-10-23。第一批 P0 已获用户开发授权；本地实施不授权推送、构建生产产物、部署、切流或通知。代码基准 `49c494ee9c73a646d1c072f5e64605c5da2db651`。生产版本与路由归属须在实际发布前重新读取，不能用本地候选代替。

## 用户选择

- 变化区绿加、红减，保留文字标识；正常前景色显示正文。现有政策卡的限制、许可颜色语义保留。
- 默认浏览包含本站更正、补录、结论文字变化、历史原因未分类、暂缓／移出当前结论。来源检查、纯页面更新作为次级类型。
- 仅 V6 内嵌模块默认近 90 天。独立历史默认全部可查记录。
- 学生影响摘要优先，但须提前生成并审核，保留证据链接；无已审核摘要先用结构化模板。比较器后续另做。
- 暂不显示未经独立证据审核的“学校政策变化”。本站 Claim 修改、来源 hash 变化均不建立学校新规。
- 明暗主题共用组件；学校随 V6 迁移逐批接入。

## P0：现有 Changes 的有界修复

适用当前共享 zone 的 `/changes`、V6 学校 `/changes/{slug}`、对应语言版本，以及当前 zone 的 changes index/latest/recent/RSS 消费链。不接管旧修订 artifact 或非 V6 路由。

- `policy_text_changed` 等既有 API 字段保留，显示标签改为“本站结论文字变化”。
- 无记录 diff 时不把当前 Claims 伪画为新增。有修订计数但没有可比较文字时显示“暂无文字对照”，不显示“没有更新”。
- 已记录的 `claim_id` 精确匹配、相同 ID、不同文本才可显示直接红绿对照；无匹配凭据的 v1 索引不展示缓存文字配对。scoped correction 本批不新增 diff。
- 更正和补录按 Claim ID 去重，新增与修改交集不重复计数；不把 evidence/metadata 计数相加。暂缓用词不暗示大学撤销政策。
- 中文优先已有中文摘要。仅内容允许按明确语言回退，UI 保持当前语言；七语界面文案覆盖。冻结文件只读，不回填历史原因或改写原文。
- 不在本批重整历史事件、过滤无关全局 release、增加分类结构或改变日期筛选。上述问题在 P1 解决。

实际发布前必须冻结 nginx 精确 URL 清单、服务、代码 SHA/BUILD_ID、数据身份及旧资源回退。共享源码中的修改不能证明旧服务或其他路径已更新。本批按 `release-routing-policy` 的 B 类评估，只构建所需 zone；没有发布授权时不执行。

## P1a：升级既有投影、接口与门禁

复用 `uapt-public-change-history-v1`，将现有导出升级为有显式版本的 v2，禁止新增平行历史体系。原 v1 与历史修订原件继续保留。v2 增加事件 ID、`rulesVersion`、逐条类别、匹配方式、旧新 Claim 文本及输入依据。

- 事件身份为 canonical slug + 原修订身份，日期不是主键。每校只生成实际相关修订事件；有明确文字变化又撤回时，两次事件均保留。
- V6 冻结修订包及逐校父链作为该修订依据；精确绑定 slug/revision/basis 的 `v6HistoryRepair` 仅修复展示投影。`v6FrozenHistory` 是有界冻结输入和交叉核对来源，不能拿 latest 重解释旧事件。
- 既有 public-change-history 的 basis 已覆盖 pages/records/history 指针、record-repairs、旧 release 与 rankings，扩展它，不能漏掉原有依据。record-repairs 作为独立修订并入，V6 前历史来自旧公开 release。
- 同事件的来源去重合并引用；冲突阻止对应范围验收。缺父修订、缺旧文、换 ID、近似匹配均保留缺口，不默认新增或认定等价。
- 历史分类只根据显式元数据和确定性规则；AI 不回溯猜原因。无法映射则“历史记录·原因未分类”。页面更新条目的现有组件来源要单独登记。

V6 overview 是内容包新增的 `family`，复用 shard manifest、`readVerifiedArtifact` 和 hash 校验；不是全站 index 的子集请求，也不把约 50KB 的完整单校历史直接塞进页面。overview 严格上限为 **10,240 字节未压缩 UTF-8 JSON**，打包时强制校验。它绑定修订、policy basis、投影 hash、rulesVersion、可查询起点、轻量日期/主题计数和最多三条预览；详情以明确 revision + slug 按需获取，同版本不一致则失败，不混入 latest。

拟新增同步合同 2.1.0 时，必须同时修改以下分派点及对应 runbook/AGENTS：

1. `scripts/policy-inventory.py`：消除未知版本跳过 typed gate 的 fail-open；
2. `scripts/uapt-release.mjs`；
3. `scripts/lib/require-policy-sync.ts`；
4. `scripts/pack-v6-release.ts`。

2.0.0 历史事件保持原验证；2.1.0 必须包含 v2 的全部检查，再增加真实事件产物、scope、basis、规则与跨面一致性检查。未知版本一律拒绝。失败用例覆盖未知版本、过期 basis、错误规则、缺学校/事件、重复、外校混入、scope 不符、陈旧 index/RSS。recent/RSS 只核对各自真实窗口和条数子集。检查真实产物，不使用布尔完成标记代替。

P1a 只改数据和门禁，候选回读通过前不切公网。

## P1b / P1c：单校历史与全站逐事件浏览

沿用 `/changes/{revision}/{slug}` 事件详情 URL，不新增 URL 体系。单校默认全部历史；全站按事件日期筛选，解决每校一条、只按最近日期过滤的问题。计数与分页从完整筛选结果计算。条目按 V6 主题顺序显示，长文字可展开。当前结论、真实 Claim 差异、官方来源分层阅读；没有同范围新旧官方文本则不展示官方原文 diff。

既有修订 URL 的索引资格保留，不自动 noindex；真正新增 URL 必须实施前逐条列出，只有明确的新增薄内容才考虑 noindex、不入 sitemap/通知集。迁移旧路由时保持自引用 canonical 和深链。P0 不改变 SEO 策略。

## P2：在现有 V6 接入同一折叠组件

仅依赖已验收 P1a，不必等待 P1b/P1c 全部完成。三条渲染路径都在 `#claims` **正前方**插入同一模块；顶部增加入口，页内导航只在“已审核条款”前增加一项，其余导航、区块和手机布局保留。

原有顺序为四问 → 主题 → 学生指引（含提交前检查）→ 工具 → 新模块 → 已审核条款分类卡与弹窗 → 暂缓 details → 官方来源卡。不得按效果图将条款/来源重做为单行折叠，或把提交检查移动到工具后。`PolicyV6ChecklistFaq includeFaq={false}` 不产生新区块。

- 默认折叠，SSR 概览最多三条，默认 90 个 UTC 日期（含当天与前 89 天）。窗口服务端计算一次传给客户端。
- 模块内筛选为 30 天、90 天、自定义，并链接“查看本校全部历史”。保留加载、失败、无匹配、完全早于记录起点、部分区间缺记录等不同状态；失败不报 0 条。
- 手机与桌面均原地展开或链接已有修订页；不实现模块内子路由、面包屑、返回栈和下一事件导航。
- 原生 details/summary、键盘与焦点/hash 展开；圆点装饰、日期 time、增减文字与图标；明暗主题、触控尺寸和实际对比度验收。

## P3：已审核摘要；比较器另期

AI 只生成候选，摘要绑定学校、修订对、主题、fingerprint、证据和独立审核记录；不继承 Claim 审核。先审核 EN/ZH，其余语言 UI 本地化、内容明确回退；未审核摘要用模板，不展示草稿。红绿区始终显示真实旧新文本，不能以 AI 缩写替代。

## 验收与发布边界

本地检查包括 `pnpm check`、独立 zone 类型检查、相关历史/匹配/本地化回归、`git diff --check`、七语与明暗/手机浏览器 QA。不用全站本机构建代替这些检查。原始政策、私有库存、held 决定、源文件 hash、历史批准保持。同步事件记录实际覆盖与有理由的排除。本地通过不等于生产语义或上线验收。
