# P1c：全站逐事件 Changes 浏览（本地验收）

2026-10-23 用户继续授权下一步；本地运行日志为 2026-10-24 UTC。复用 `changes-v6-p0` 工作树，分支 `codex/changes-v6-p0-20261023`，基准 `49c494ee9c73a646d1c072f5e64605c5da2db651`。本批未推送、部署、生产构建、重启生产服务、切指针或发送通知。

## 行为

- `/changes` 和七种语言版本在选中 P1a v2 包后按真实事件显示，每校的多次修订分别保留。默认全部可查历史、主要记录更新类型；默认 779 次，全部类型 786 次，涉及 475 个历史学校标识。来源检查等 7 次次级事件通过类型筛选查看。
- 搜索学校或修订版本，提供日期、更新类型、主题／原有分类、国家／地区筛选。计数从完整匹配集合计算后按每页 8 条分页，改变筛选回到第一页。日期取事件自己的发布时间，按 UTC 日期双端包含，缺日期记录保留在全部历史中，自定义日期不会给它们补造日期。
- 主题与类别同时筛选时核对同一实际条目，不能拿事件级两个独立数组的交叉出现当成匹配。V6 主题优先排列；已有历史分类继续独立保留，新增招生／申请材料的七语标签，不重新归类历史 Claims。
- 桌面为时间线与修订详情两列；手机顺序排列，点选后焦点进入详情。文字按主题折叠，真实增删保留绿加红减与旧／新文字标签。复用 P1b/P2 的 `ChangeEventContent`，不生成学校原文 diff、AI 摘要或政策生效日期。
- URL 保留本期日期、类别、主题、国家、搜索、页码和明确的 `slug:revision` 点选身份，刷新／浏览器历史可恢复。canonical 保持各语言 `/changes`；原有学校历史与修订深链不变，未新增页面 URL、noindex、sitemap 或通知集。
- 首屏只传 8 条轻量预览、筛选项和计数，筛选后读取同版本分页接口；详情只按明确包版本＋学校＋修订获取。v2 失败时显示失败，不伪装成空结果，也不回退旧聚合。v1 尚未迁移时保留原页面和接口。

## API 与兼容合同

新增的是 API 入口，不是新的页面体系：

| 路径 | 含义 |
| --- | --- |
| `/api/public/v1/changes/events/{packageRevision}/index.json` | 分页事件索引；支持 `locale/q/kind/topic/country/from/to/page`；默认主要类型、全部日期、每页 8 条 |
| `/api/public/v1/changes/events/{packageRevision}/latest.json` | 每个历史学校标识最近一次实际事件，包含无日期学校的可查记录；不是整站 release diff |
| `/api/public/v1/changes/events/{packageRevision}/recent.json` | 真实日期窗口内、从新到旧最多 50 个事件；支持显式时区时间 `start/end` 及 1–100 的 `limit` |

三者声明同一 projection hash、basis、rulesVersion 与 package revision。默认 recent 窗口为当前包内首个至最后一个有日期事件，再取最近 50 个，不暗示最近 90 天。窗口及限制随响应提供。

原 `changes/index.json`、`changes/latest.json`、`recent-changes.json` 默认 JSON shape 与语义保留；通过 `?view=events&revision={packageRevision}` 可读取对应新视图。尤其旧 latest 继续代表 release diff，不偷偷改成逐校最近修订。既有 widgets 继续消费兼容旧 shape，本期未将它们改成逐事件列表。

RSS 在选中 v2 时从同一有日期事件窗口取最近 50 个，保留各次事件的唯一 GUID 和既有修订 URL，附 projection 身份及窗口；缺日期事件不伪填“现在”。v2 读取失败返回 503，zone 保留上游状态码。未选 v2 时原 RSS 保留。未知包版本 409、非法筛选 400、不存在学校 404、校验失败 503。

当前生产指针仍为 v1；上述新消费者只在本地 development 选择 P1a 不可变公开导出包验证，未从私有库存加载生产资料。

## 实测

- `pnpm check`、独立 zone 和脚本类型检查、`git diff --check` 通过；P0/P1a/P2/P1b/P1c 相关回归 34/34。
- 七语 `/changes`：HTTP 200、单一 h1、单一 JSON-LD、各语言自引用 canonical。28 组浏览器状态（七语 × 390/1440 × 明暗）均无横向溢出或 pageerror。没有实体手机或屏幕阅读器验收。
- 真实分页 API 连续读取 99 页，得到 786 个有序且不重复事件 ID；与冻结投影逐项相同，475 个学校身份完整。latest 返回 475 个不同学校的实际事件；recent 与 RSS 的 50 个事件 ID 完全一致，projection hash 一致。旧三接口默认 shape 及 opt-in 视图均 HTTP 200。
- 哈佛默认 4 次修订；5 月 1 日至 6 月 30 日得到 6 月 14 日与 5 月 26 日两条，并提示部分覆盖。刷新保留日期和第二条点选身份；全站第二页与类型筛选重置第一页通过。
- ANU `v6-target-r7-candidate-20261021` 在预览级同时包含“补录”和“考试”，但没有同一条目同时满足两者；真实联合筛选正确排除该事件。
- 索引接口 503、详情接口 503、外国 projection hash 响应均显示明确失败；恢复后重试成功。错误状态不显示匹配零次；成功但无结果时才显示零次及范围提示。六种非法／过期接口请求分别得到预期 400/404/409。
- 学校历史、真实修订页和 Harvard V6 学校页均 HTTP 200、无溢出；V6 模块保持单一实例。这些页面没有请求全站 Changes index。旧 HKU 全局发布 artifact 的 Harvard 深链仍 200，原始展示组件保留，不纳入新事件布局验收；它仍有原来的 h2 标题结构，不能据此宣称旧 artifact 已全面迁移 V6。
- 已人工查看桌面实际红绿文字对照、默认全站列表和手机浅色截图。截图是本地浏览器产物，不是概念稿。

私有证据在 `.local/changes-p1c/`，包含原始浏览器结果、源码快照、hash basis、截图和 audit 同步事件。P0/P1a/P2/P1b 验收包保持原样。canonical 的开发 origin 沿用 `localhost:3000` 配置；本期检查路径，生产 origin 需正式发布时重新验收。

## 后续与发布边界

本批是新消费者的本地迁移，不构成合同 2.1 正式候选／公网六面同步凭据。还需由发布适配器从实际运行表面提取有范围、窗口和 basis 的 receipt，完成正式配对打包、候选与公网回读。既有 review、PARTIAL/UNVERIFIED、held、原文和数据指针没有改变。

这次涉及全站浏览与公共 API 合同，发布须按 `release-routing-policy` 协调主站 OCI 产物与 zone：主站 3100 的对应 API／配对数据先验收，zone 才能消费同版本；仍须通过统一生命周期、容量和回滚门禁。不能只发布局部页面便宣称全部消费者同步完成。

下一阶段 P3 为提前生成、独立审核并绑定证据的摘要流程；比较器另期。本批未显示或批准任何未审核 AI 文字。
