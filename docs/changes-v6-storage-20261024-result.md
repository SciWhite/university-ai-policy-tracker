## 防止再次累积

[磁盘与保留规范](release-storage-policy.md) 和 AGENTS 已写入工作区及 main。服务器已安装 root 拥有的权威控制器，SHA256 `920501405bde8074b9f17755e5c6844db561521bbf2d901558bcfedc7c8e11e3`，并启用以下门禁：

- 主机始终预留 20GiB、至少 100 万可用 inode；UAPT 项目总预算 72GiB。
- 每次产物上限：main 6GiB、shared-web 3GiB、shared-mcp 3GiB；不自动上调。
- 下载、解压、依赖、构建、候选、归档、收尾七阶段都须声明相对检查时刻的剩余累计峰值。构建前、切换前实时核对，实际包体也须过上限检查。
- 全部 release 目录须有绑定同一发布依据且 24 小时内复查的保留收据。缺预算、缺阶段、缺分类、空间不足或包体超限即拒绝；切流前再次核对目录集合。
- 现行保留台账为 `/srv/uapt/operations/release-lifecycle/current-retention.json`。它列明 36 个目录理由；下次发布必须重新复查并绑定新依据，不能直接复用过期台账。
- 用已安装控制器和固定服务槽位；继续禁止按学校新增常驻服务、上传完整工作区或按日期/V4/V5/V6 名字自动删除。

真实服务器容量下的零新增占用检查与保留收据验证通过；缺预算、侵占主机余量、共享包超限、缺归档峰值、新增未分类目录、项目预算超限六项均被已安装控制器拒绝。这是门禁功能验收，不冒充新发布演练。
