## 2. 统一入口与增量登记

统一的是身份、版本、证据关联和状态查询，不强制把所有全文复制进一个 JSON，也不把登记库接为未经审核的生产数据源。

关系模型：学校身份 → 官方来源 → 来源版本/快照 → 主张或专题事实/工具记录 → 审核裁决 → 展示版本 → 发布版本 → changes/通知及读回记录。

实施前使用逻辑工作区标识定位输入：primary-workspace、scene-workspace、repair-workspace、approved-content-workspace、openclaw-audit-workspace。机器绝对路径只在私有 resolver 中维护；可移植单校包使用包内相对路径、artifactId 和哈希。迁移后仍须验证实际对象存在且字节匹配，不能只替换路径字符串。

增量登记至少包含：

- schemaVersion、inventoryVersion、requirementsVersion、父库存哈希、runId、生成时间和明确统计口径。
- 稳定 recordKey、学校身份、资料命名空间、原始 ID、关联 ID；保留公开 Claim ID。
- 输入逻辑路径、输入文件哈希、原始/有效事实哈希、来源版本及证据位置。
- 操作类型：add、revise、supersede、retire、duplicate_representation、conflict、review_update、display_update、publication_update；明确旧新引用和原因。
- 审核、展示与发布状态分别记录；缺失证据时不得猜测状态。
- 发布依据保留全局 manifest、局部修复 revision/哈希、必要运行时内容包和 MCP catalog 标识；单一全局 releaseId 不足以表示组合部署的最新内容。

历史源文件和基线索引只读保留；新库存引用父快照并输出新的冻结清单。不得把原有输入哈希改成当前哈希以消除漂移。

## 3. 独立审核维度

建议登记五个独立维度：evidence_binding、semantic_veracity、temporal_validity、display_eligible、release_approved。这些是待实现的内部审核字段，不是已经生效的公开 API 契约；各维度须有状态、依据、审核时间和审核者/执行来源。

证据绑定通过只证明引用与冻结对象匹配。语义审核另外检查主体、must/should/may、条件、例外、正式规则/指导/案例区别。当前有效性另外核查适用年度、替代文件和官方冲突。展示及发布资格不得从前面某一项自动推导。

工具访问、机构采购、官方推荐、数据安全批准和作业使用许可保持独立。一般不端程序与 AI 明示规则保持独立。学校身份归并不意味着不同学院、校区、群体、旧新机构的规则合并适用。

## 4. 可扩展采集与审核要求

建立带稳定 requirementId 的版本化要求清单。每次任务保存使用的 requirementsVersion，并对每项保存检索入口、官方来源、结果和缺口原因。要求完成有界检索及结果登记，不要求学校必须存在每类规则。

初始范围：

1. 作业、考试、课程裁量、具体 AI 用途、许可条件及例外。
2. 披露、引用、过程记录、提示词/输出、格式要求与建议性质。
3. 违规类别、AI 检测及证据限制、解释机会、调查与听证。
4. 处分机关、可能后果、回应/复核/申诉阶段、期限单位及起算点、延期和支持。
5. 隐私、数据等级、机构账号、日志与保存、训练用途、第三方传输和适用人群。
6. 工具名称/版本、访问资格、成本、席位、认证、推荐、限制与用途审批。
7. 研究、学位论文、出版、版权、伦理、安全评审和采购。
8. 合理调整、AI 评分、教师上传学生作业及其他新专题。
9. 来源状态、官方权威层级、原文语言、日期类型、替代来源和完整上下文。

官方发现应覆盖学术/考试管理、教学中心、图书馆、IT、研究与政策 PDF 等适用路径，不以工具页检索替代其他范围。所有公开 Claim ID 必须逐条覆盖，source_status、privacy、research、procurement 等不能被主题筛选漏掉。

新增要求不封死枚举，也不自动改写旧审核。旧任务对新增 requirementId 标为未检查，按差额补查。not_found、not_explicit、not_searched、source_failed、scope_unclear、needs_review 等缺口分别保存，不将未发现或访问失败写成无政策。

原始抓取时间、来源公布/生效/修订日期、claim 核查时间、审计时间、展示和 tracker 发布时间分别保存。缓存生成和文件 mtime 不得冒充新核查日期。

## 5. 来源完整性与重复调查

原始 HTML/PDF、完整冻结文本和截图保留私有；公开仅输出必要短引文、URL、哈希和引用元数据。保留原文，翻译和摘要不能替换原始证据。

分别标识 raw bytes hash、normalized text hash 和 normalizationVersion。验证连续原文、必要上下文、PDF 实际页码/章节；字符匹配与规范解释分开。原文字词或否定、条件、范围不得通过“归一化”消失。

对 12 组同哈希多 URL 建独立调查表，记录每个 sourceUrl、finalUrl、历史快照、取回方式、hashKind、正文和范围。调查结果可为相同内容、确认重定向、独立来源、抽取失败或证据错配；不得提前写成多数属于别名。URL fragment、编码、大小写、查询参数不得统一粗暴删除。

同 URL 的历史快照按版本保留。相同文件字节可以复用存储对象，但各来源/采集/审核引用关系仍须保存。

## 6. 单校审计包与协作输出

单校包包含包内 manifest、完整公开 claims、页面补充事实、工具记录、学生快照依据、来源及历史版本、候选/暂缓材料、已知冲突、requirements coverage 和缺口。不同命名空间分别统计，避免把派生工具与基础 claim 当成两个独立政策事实。

ChatGPT 审计必须独立联网核查；存档只辅助定位和版本比较，不代替当前官网。输出中文报告和结构化审核 sidecar，覆盖全部对象 ID，记录审核类别、严重程度、官方 URL、原文与准确位置、范围、规范强度、日期依据、英文修订建议及剩余 ID。

Codex 验证输入依据、ID 全覆盖、证据关联和字段契约，实施修复与派生输出，完成候选验收。身份冲突、官方冲突或未完成审核保持暂缓；报告不自动赋予发布或摘要批准。单校审核任务按既定队列停在当前学校，不自动继续下一校。

## 7. 每次任务与发布的同步清单

每次爬取、审计、修订、展示/发布或索引任务都生成 task/event 记录，对同步项保存 updated、not_required_with_reason、pending 或 failed 及依据。不同事件可以引用同一变更，不重复制造事实。

| 关联输出 | 必须核对的内容 |
| --- | --- |
| 资料入口 | 库存版本、增量登记、知识摘要、SQLite 缓存的版本与新鲜度 |
| 公开数据 | 大学 JSON、claims/evidence/officialSources、数据导出、字典、校验和、统计、覆盖与分析 |
| 工具与学生摘要 | 工具派生/专项目录关联、student snapshot 依据指纹和独立审核状态 |
| 检索 | MCP catalog、允许返回的 claims、remainingClaimIds 对账、搜索与学校名称/排名映射 |
| 展示 | 大学及补充页面、适用语言和回退、锚点、必要运行时内容包与数据指纹 |
| changes | 学校变化页、历史/修订页、变化索引、大学 latest diff、近期组件、RSS；全局 latest 与局部修订语义明确 |
| 发布与索引 | 发布 manifest、精确受影响 URL、sitemap/可索引资格、通知 ledger、实际公开读回和回滚标识 |

每次公开政策变更必须在同一发布范围更新相应 changes；仅政策 JSON 更新不算完成。新门禁须覆盖一般 manifest 提升、局部 record repairs、工具和已发布补充事实等实际发布入口；现有局部门禁不能当成已覆盖所有入口。

无政策变化的成功抓取记录检查事件；获取失败记录来源健康事件；索引提交记录通知事件。不得伪造政策 diff，也不得用无变化的扫描时间刷新未核查 claims。公开 metadata 或 source-status 更新是否需要独立变化条目，按实际发布内容和事件类型明确判断。

IndexNow 等通知只在授权发布后提交符合当前公开 sitemap/索引资格的变更 URL；接受请求不等于搜索引擎已收录。不因本计划创建后台自动化或发网络通知。

## 8. 推进阶段和验收

### A. 保存基线并建立增量登记（本地材料阶段已实施，异构批次进一步规范化待办）

- 保留 2026-10-07 库及其输出/输入清单，生成新快照而非覆写旧库。
- 从 repair-workspace 登记 MIT 28/Imperial 17 全量记录、来源证明、历史与候选版本、暂缓/摘要状态、changes journal/cache 以及实际发布证明。
- 从 approved-content-workspace 登记 OpenClaw 31 包/38 修订主张和 Bing 89 展示事实的候选；重新确认当前是否被发布或替代。
- 登记 10 月 7 日之后的 V5 批次、验收、定向修复及运行时发布，不把页面测试推断成全部语义审核。
- 输出增量总表：新增、修订、替代、冲突、重复表示、审核/展示/发布状态变化及未解析对象。

验收：输入只读；所有导入有来源及哈希；父快照匹配；旧历史可查询；现行已发布修复不会被旧库存回退；状态计数与对象集合可复算。每所学校有 declared coverage 和剩余项，不能静默漏掉批次。

### B. 对账存量并实现可移植审计合同（材料对账与合同验收完成，政策语义及现行版本保留待审）

- 核对来源对象可取回性、引文位置、版本、身份映射、复用/冲突关系和独立审核维度。
- 调查同哈希多 URL，解决候选、页面、公开 JSON 和发布状态间差异。
- 实现 requirements registry、单校包及结构化审计输出校验；用 MIT/Imperial 验证完整对象覆盖和暂缓保留。

验收：搬迁后的包仍可校验；所有 ID 对账；缺口和冲突可查询；private/public 边界可验证；校验通过不改写审核或发布批准。

2026-10-11 的 B 结果见 [完整报告](policy-evidence-reconciliation-20261011.md)。已覆盖 11,767 条记录及 14,683 个证据引用；12 组同哈希多 URL 完成有界联网调查，访问受限和旧哈希未复现的部分明确保留。MIT／Imperial 增强包分别覆盖 101／68 个对象（包括各 4 个学生摘要版本），搬迁验收通过。34 项合同测试和摘要脚本类型检查通过；351 组内容差异、2,936 个来源级补查组和全部未做独立政策审计的要求仍有明确清单。

### C. 按明确缺口补抓并实现同步门禁（有限补抓与本地门禁已完成，政策复核和实际发布验收另行执行）

- 仅对缺原文、来源替换、新要求或未检索范围补抓；冻结证据足够的条目直接复核。
- 把同步矩阵接入实际发布路径，并验证缺失 changes、过期 MCP/摘要/运行时依据等会阻止任务被记为发布完成。
- 更新知识摘要及缓存的时效检查；隔离旧报告和当前 runbook。

验收：实际变更逐项可追溯；无需更新项有理由；受影响公开路径及必要对照通过；失败可回滚。是否构建、构建范围与上线授权另按当前发布规则处理。

2026-10-11 的 C 结果见 [阶段报告](policy-evidence-phase-C-20261011.md)。2,936 个 source-level 问题组对应的 2,807 个 URL 全部完成有限采集尝试，2,294 个 URL 取得当前正文，513 个保留访问/错误/格式限制；126 个版本组复现声明的原始哈希，仍未自动判定政策正确。维护提升、摘要实际 re-pin、IndexNow 实际提交和旧修复脚本适配器均要求同步合同 2.0.0；小更新/全量发布 runbook 增加前后阶段校验。历史工作区未原地改写，旧入口未经当前适配器不得重跑；生产程序尚未升级。

MIT／Imperial C 包保留 101／68 个对象及 28／17 个完整公开 Claim ID，新增 2／1 个当前来源响应链接，搬迁和 ZIP 完整性校验通过。知识/缓存/registry 有独立时效检查。58 项 Python 合同测试、4 项 release-chain 回归、5 项 IndexNow 库测试、相关脚本类型检查通过；本地 loopback 通知 fixture 不构成对搜索引擎的提交。两校公开 JSON 再次与冻结主张一致，未新增语义判定或改变暂缓状态。

全仓库 `pnpm check` 现已通过：校验器只将相同 ID 且全内容相同的发布清单副本视为同一节点，冲突副本仍拒绝；三份完全相同的生成类型副本另存隔离目录。实际发布清单、历史政策与应用源码未为排除这些阻断而改写。A/B 当时的失败日志继续保留，不能把当前通过结果追溯写成历史通过。

目标是建立有完整范围与明确缺口的基线，再依时间、来源版本和新增要求增量复核；不承诺一次整理后所有事实永久正确。

## 9. 本轮实施范围与限制

`scripts/policy-inventory.py` 登记 16 个逻辑工作区的选定材料目录，保留父基线及原始字节对象，输出 JSON、SQLite、增量、批次登记、来源级缺口和版本化要求。860 个历史学校键继续保留；815 个键实际具有规范化记录，二者不能混用。公开依据是历史基础数据加 MIT／Imperial 发布修复，不是全部学校最新政策。
