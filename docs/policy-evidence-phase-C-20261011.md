## `pnpm check` 阻断的处理

第一项根因是 current 与 history 的 `public-release-20260924-002` 清单完全相同，SHA256 均为 `63722e1a79847542a483049ac3a52b3431337c6f623716487ead0c93304bedd1`。旧校验器把两份文件当成两个时间节点，错误要求当前 release 指向自己。新的校验按 releaseId 去重，只允许全对象内容相同的副本；内容冲突、未知前项、自引用、跳过真实前项和 current 不是最新版本仍报错。两份发布清单均未删除或改写。

解除该阻断后，类型检查暴露 `.next/types` 中三份与原文件字节相同的 ` 2.ts` 副本。已将副本及哈希凭据移入私有隔离目录，保留原生成文件；没有放宽 tsconfig 或改写应用逻辑，也未为此构建全站。

完整 `pnpm check` 已通过，包括 dataset/public-data 校验、递归 typecheck 和 lint。当前 dataset 校验计数为 40 个唯一 published releases、1 个相同归档副本、828 所学校、5,495 条 claims；这只是此 checkout 的数据合同检查，不是全部政策事实正确率。

本轮额外验收：58 项 Python 合同/拒绝路径测试、4 项 release-chain 回归、5 项 IndexNow 库测试、3 个实际入口无凭据拒绝测试，以及相关脚本类型检查通过。无凭据提交在网络调用前拒绝，所有测试未改写当前公开 release 清单。通知完成事件的正向测试只向临时 loopback 接收器发送一份 fixture 请求，未通知任何真实搜索引擎。

本次操作先完成本地任务范围。后续若要发布这些代码，仍须冻结允许文件集、按 release routing 选择有界发布方式、验收候选并另行取得上线授权；旧 release/服务/内容指针继续保留用于回滚。
