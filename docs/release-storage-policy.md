# 发布与磁盘保留规范

2026-10-24。与 release-lifecycle.md、release-routing-policy.md 和同步合同一起执行。新开发统一 V6；尚未迁移的 V4/V5 功能、政策历史、证据和 held 决策继续保留。

## 版本与发布范围

- 程序版本、学校政策修订、页面布局版本分别记录。换成 V6 不制造大学新政策，也不复制全部历史。复用共享组件与页面服务，不按学校另建常驻服务。
- 兼容内容走独立不可变内容包；小范围界面、受控学校或代码变化只构建共享 zone。全站布局、框架或广泛契约变化才走一次全站构建。不能为了把分支合入 main 再构建一次已验收的应用。
- main 保存已整合源码。生产台账分别记录各实际服务的 SHA、BUILD_ID、内容与数据指针；不能因为 main 前进就宣称所有服务已更新。禁止覆盖有未提交改动的旧工作区。

## 生产文件分层

| 内容 | 保存规则 |
| --- | --- |
| 程序运行包 | 各角色当前产物、明确的上一份已验收回滚产物、最多一组临时候选。其他完整程序版本须有具体引用或进入冷归档 |
| 公开政策与历史 | 按学校/修订、manifest 和哈希管理，保留访问能力；不随每次程序发布重复复制完整历史 |
| JS/CSS 与公开图片 | 独立版本路径；保留旧 URL，核对哈希、类型、缓存头与公网。静态目录不得承载整个 .next、动态请求或私有原件 |
| 原始证据、审核包 | 私有独立证据库。保留原件、来源身份、时间、历史批准与未决项；只导出公开白名单字段 |
| operations | 运行 catalog、有效台账、事务与恢复记录需登记保护。不能按目录时间整体清理 |
| 缓存与中间材料 | 发布清单列出用途、上限、失效与清理条件。唯一源码/补丁、证据、失败记录与恢复材料不作为普通缓存 |

生产源码/构建包使用明确文件清单，仅带运行和该次构建必需的应用、依赖、公开数据及资源。完整 Git 历史、其他聊天工作区、截图、私有库存、审核草稿、旧压缩包和 unrelated 项目不得随包上传。历史数据加载依赖尚未分离的地方保留明确缺口，不能先删后补。

## 每次发布的容量门禁

服务器权威配置为 `/srv/uapt/operations/release-lifecycle/policy.json` 中的 `diskCapacity`。根分区由其他项目共享，可用空间与 UAPT 自身占用必须同时检查。项目总预算不会随每次发布自动上调。

统一入口使用服务器 root 拥有的 `/usr/local/libexec/uapt-release-lifecycle.py`。最新版 Node helper 在服务器优先调用此副本；历史 checkout 的旧控制器、一次性 cutover 或 publisher 不得替代它。

新计划提供：

- `diskBudget`：schema `uapt-release-disk-budget-v1`、精确 basisSha256、role、artifactMaxBytes 和 peakAdditionalBytesByStage。
- 七个阶段全部列出：download、unpack、dependencies、build、candidate、archive、finalization。每项表示**相对本次检查时已占空间，该阶段仍可能增加的累计峰值**；用最大项做准入。已完成部分可填 0，但不能把解压后的大小当压缩包大小，不能遗漏回滚/候选并存及同盘归档临时空间。
- `retentionReceipt`：路径与哈希，绑定同一 basis，schema `uapt-release-retention-v1`。24 小时内复查全部实际 release 根目录，每个分类为 active/candidate/rollback/held 并写具体理由；未分类、陈旧清单或 archive_pending 不能通过。

构建前及切换前读取实时可用字节、inode、UAPT 单次 du 总占用；检查主机保留量、项目总预算和每角色包体上限。构建完成后核对实际包体，不只相信估计。内存原门禁同时生效。下载和解压前先按同一预算核对主机余量；不得先占满磁盘再准备计划。异常包体增长须查明原因，不临时抬高上限。

生产 diskCapacity 是本轮安装后才生效的行为；历史无此字段的 policy 仅供恢复/合成测试兼容，不得用于新发布。更新服务器 policy、控制器或预算不是普通内容发布的隐含权限。

## 归档与删除

1. 建逐版本引用表：有效服务配置及环境、进程 cwd/fd/maps、完整 Nginx include、内容/MCP/历史指针、符号链接、定时任务、未完成事务及明确回滚依据。历史文档提到路径与运行依赖分开记录。审计不自动授权删除其他聊天或项目。
2. 冻结精确白名单与依赖。按 inode 计算净释放量；多目录硬链接不能逐目录 du 后相加。包外链接要解决或明确保留其恢复依赖，不默默跟随并打包秘密。
3. 完整可恢复归档放服务器之外；保留文件、链接、模式、必要配置及恢复依据。记录 SHA256，核对归档字节并进行隔离恢复检查。单个恢复样本不能声称所有历史版本已重新运行验收。
4. 删除前重新检查引用、白名单与源内容。任何新增引用、漂移、未完成发布事务、归档/恢复失败都保持原目录。只删除已验收白名单，保存逐目录结果及释放前后容量；随后检查页面/API/MCP和服务。
5. 每次 complete 后更新保留台账：新 active、前一回滚、候选清空、其他依赖理由、需归档项和到期复查时间。下一次发布不接受未解释的旧目录积累。禁止按名称、日期、学校或 V4/V5/V6 标签直接删除。

永久冷归档应在独立磁盘或既有对象存储。当前电脑上的保留包是临时恢复材料，必须记录大小和剩余空间；未选长期去处前不能无限转移服务器占用，也不能删除唯一已验收归档。这里不授权新开付费存储或设置按年龄自动删除证据。

## V4/V5 退出

按学校核对默认/别名/语言路由、证据、旧 Claim 深链、历史 diff 和有价值的 V5 程序内容。V6 公开验收和回滚窗口结束后，才移除无人调用的旧展示代码。旧程序目录的退出依据是实际引用与恢复验收，不需要等所有学校完成 V6。

## 2026-10-25 暂留期限与临时材料检查

服务器开启 `retentionEnforcement` 后，每个 `held` release 和发现的临时材料必须有 `heldSince`、带时区的 `reviewBefore`、具体 `nextAction` 和保留理由；最长 24 小时。到期只会**阻止下一次发布**，不会自动删除运行文件或证据。需要延长时须另行解决依赖或做明确的运维评审，不能在普通发布中修改期限。

权威 `current-retention.json` 保存首次暂留时钟。新发布收据必须沿用同一材料的首次时间和不晚于原定的期限；修改 checkedAt、重新计算文件哈希或把失败版本改叫 rollback 不能消除欠账。held 改为 active 必须有实际运行目录匹配；原暂留已经过期时仍拒绝。归档并经最新引用复查删除后，该原件才从实际集合和台账退出，归档与恢复凭据继续保留。

磁盘检查同时发现 policy 明确列出的 `builds/*`、`candidates/*`、operations 源码压缩包及暂存公开内容路径。它们须逐项列在收据 `temporaryArtifacts` 中，以绝对 `path` 为键，使用同样有界的 held 字段；遗漏、新增或软链接冒充普通材料均不能绕过检查。发现规则跳过符号链接，不把运行 catalog、证据或 operations 整目录归入垃圾。旧临时目录先登记现有用途和具体处理动作，按白名单另行归档。

执行 `sudo /usr/local/libexec/uapt-release-lifecycle.py retention` 可只读核对当前台账、真实目录和暂留期限。prebuild、gate 及切流前也执行同样检查。新失败候选必须立即登记材料和期限；complete 后的台账更新必须保留全部现存 held 的原始时间，旧脚本若丢失字段会被拒绝。禁止为通过门禁清空权威台账、忽略临时材料或调高容量预算。

首次暂留时钟另存 root 拥有的 `hold-clocks.json`，由 `retentionEnforcement.clockRegister` 指定。即使普通 current-retention 清单被整份重写，也不能延长已记录的期限。prebuild/gate 在同一发布锁中登记首次见到且已验证的 hold；失败/完成后的台账补写须执行 `record-retention` 校验并登记新增 hold，再只读执行 `retention`。归档移除后的旧时钟继续保留作追溯，禁止复用旧 release 路径或重置时钟文件。

## 明确授权的单次发布豁免

用户明确授权放宽发布限制时，运维可在 `retentionEnforcement.releaseDeferral` 记录精确依据的限时豁免：schema `uapt-retention-release-deferral-v1`、basisSha256、authorization、approvedAt、expiresAt、nextAction 和逐项原始 name/path、heldSince、reviewBefore。最长24小时，只跳过列明材料的到期阻断；不延长原始时钟、不删除材料、不豁免容量、未分类材料、证据或回滚检查，也不自动适用于下一版本。到期仍需处理依赖或归档，不能自动续期。豁免及控制器变更单独备份审计；不重建已经验收的页面产物。
